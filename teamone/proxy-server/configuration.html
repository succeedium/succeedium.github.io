TeamOne Proxy Server Configuration ​

This page describes the common TeamOne Proxy Server configuration used by both installation models:

  • SSL managed by a load balancer
  • SSL managed directly by the TeamOne Proxy Server

The main configuration file is:

text
teamone-server-distr/config/.env

For questions or assistance, contact support@succeedium.com.

OAuth / SSO Allowed Hosts ​

PROXY_OAUTH_ALLOWED_HOST_PATTERN controls which hosts can be used by the TeamOne OAuth / SSO endpoints, including:

text
/oauth/login/
/oauth/token/
/oauth/logout/

For IBM Planning Analytics Local, SSO is commonly handled through IBM Cognos Analytics.

The allowed host should normally match the Cognos Gateway hostname configured in the ClientCAMURI parameter in tm1s.cfg.

Example:

ini
ClientCAMURI=https://cognos.company.com/ibmcognos/bi/v1/disp

Configure:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=cognos.company.com

Use the hostname only, not the full URL or path.

If there are multiple Cognos Gateway hosts, separate them with commas:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=cognos-prod.company.com,cognos-qa.company.com

Wildcard patterns are also supported:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=*.company.com

If Cognos SSO is not used, configure a non-matching placeholder value:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=disabled.local

IBM Planning Analytics / TM1 Allowed Hosts ​

PROXY_ALLOWED_HOST_PATTERN controls which IBM Planning Analytics / TM1 hosts can be accessed through the TeamOne Proxy Server.

Use specific TM1 hostnames where practical:

properties
PROXY_ALLOWED_HOST_PATTERN=tm1-prod.internal.company.com,tm1-dev.internal.company.com

A wildcard can also be used for a trusted internal domain:

properties
PROXY_ALLOWED_HOST_PATTERN=*.internal.company.com

Avoid overly broad patterns such as:

properties
*
*.com

in production environments.

Applying Configuration Changes ​

After updating teamone-server-distr/config/.env, recreate the TeamOne Proxy Server containers so the new environment settings are applied:

bash
sudo docker-compose -f teamone-server-distr/docker-compose.yml up -d --force-recreate

Verify the TeamOne Proxy Server ​

Open the configured TeamOne Proxy Server URL in a browser:

text
https://<teamone-proxy-fqdn>

Confirm that it displays:

text
TeamOne is up!
