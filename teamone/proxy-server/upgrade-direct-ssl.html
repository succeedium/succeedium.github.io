TeamOne Proxy Server Upgrade Guide – SSL Managed by TeamOne Proxy Server ​

This guide describes how to upgrade the TeamOne Proxy Server when the SSL/TLS certificate and private key are installed and managed directly on the TeamOne Proxy Server.

For questions or assistance, contact teamone@succeedium.com.

Step 1: Back up the SSL certificate and private key ​

Navigate to the directory containing the existing teamone-server-distr folder.

Back up the current SSL certificate and private key:

bash
sudo cp -f teamone-server-distr/cert/teamone.* ./

This copies the existing certificate files to the current directory before the upgrade.

Step 2: Download the TeamOne Proxy Server archive ​

Download teamone-server-distr.zip using the download link provided by Succeedium.

If the target server does not have internet access, download the archive on a computer with internet access and copy it to the target server.

Step 3: Unzip the archive ​

bash
sudo unzip -o teamone-server-distr.zip

Step 4: Stop and remove the existing TeamOne containers and images ​

bash
echo "Stopping TeamOne containers..."
sudo docker stop teamone nginx 2>/dev/null || true

echo "Removing TeamOne containers..."
sudo docker rm teamone nginx 2>/dev/null || true

echo "Removing TeamOne images..."
sudo docker rmi teamone-server-distr:latest teamone-nginx-distr:latest 2>/dev/null || true

Step 5: Load the new Docker images ​

bash
sudo docker load -i teamone-server-distr/images/teamone-server-distr.tar
sudo docker load -i teamone-server-distr/images/teamone-nginx-distr.tar

Step 6: Restore the SSL certificate files ​

Restore the certificate and private key:

bash
sudo cp teamone.crt teamone-server-distr/cert/
sudo cp teamone.key teamone-server-distr/cert/

Step 7: Review the configuration files ​

Review:

text
teamone-server-distr/config/.env
teamone-server-distr/config/default.conf

For a direct SSL deployment, the active Nginx configuration should use the HTTPS template:

text
nginx-https.conf.example

If you need to recreate default.conf, use:

bash
sudo cp -f teamone-server-distr/config/nginx-https.conf.example teamone-server-distr/config/default.conf

Review the shared TeamOne settings before starting the upgraded version.

See:

TeamOne Proxy Server Configuration

Step 8: Start the upgraded TeamOne Proxy Server ​

bash
sudo docker-compose -f teamone-server-distr/docker-compose.yml up -d

Step 9: Verify the TeamOne Proxy Server ​

Open:

text
https://<teamone-proxy-fqdn>

Confirm that it displays:

text
TeamOne is up!

Step 10: Verify TM1 connectivity ​

Confirm that the TeamOne Proxy Server can still reach an approved IBM Planning Analytics / TM1 REST API endpoint.

Example:

text
https://<teamone-proxy-fqdn>/?url=https://<tm1-host>:<tm1-rest-api-port>/api/v1/$metadata

If the TM1 REST API uses HTTP instead of HTTPS, use the corresponding http:// TM1 URL.

If the upgraded TeamOne Proxy Server is not starting, is not reachable, or cannot connect to IBM Planning Analytics / TM1, see:

TeamOne Proxy Server Troubleshooting
