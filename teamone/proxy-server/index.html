About TeamOne Proxy Server ​

TeamOne Proxy Server enables TeamOne for Google Sheets to connect securely to IBM Planning Analytics (TM1) environments that are not directly accessible from the user's browser.

It is typically used with IBM Planning Analytics Local when:

  • IBM Planning Analytics is hosted inside a private corporate network
  • access to TM1 must be routed through a customer-controlled network endpoint
  • browser-compatible communication with the TM1 REST API is required
  • IBM Planning Analytics uses Cognos-based single sign-on
  • the customer wants to restrict and control which TM1 systems TeamOne can access

The TeamOne Proxy Server is deployed and managed within the customer's own infrastructure. Succeedium does not host the customer's TeamOne Proxy Server or IBM Planning Analytics data.

How TeamOne Proxy Server Works ​

TeamOne runs inside Google Sheets and communicates with IBM Planning Analytics through the user's browser session.

For IBM Planning Analytics Local deployments, the communication flow is typically:

text
Google Sheets / User Browser
        ↓
TeamOne for Google Sheets
        ↓
HTTPS
        ↓
TeamOne Proxy Server
        ↓
TM1 REST API
        ↓
IBM Planning Analytics / TM1

The TeamOne Proxy Server acts as a controlled communication layer between TeamOne and IBM Planning Analytics.

It is responsible for:

  • forwarding approved requests to IBM Planning Analytics / TM1
  • supporting browser-compatible communication and CORS handling
  • supporting authentication and SSO flows where applicable
  • restricting proxy requests to approved TM1 hosts
  • providing centralized request handling and logging

The TeamOne Proxy Server does not provide independent access to IBM Planning Analytics and does not replace the IBM Planning Analytics security model.

All TM1 requests remain subject to the authenticated user's IBM Planning Analytics permissions.

Data and Security ​

The TeamOne Proxy Server does not persist IBM Planning Analytics cube data.

Data is forwarded between TeamOne and IBM Planning Analytics in real time and exists within the proxy only for the duration of the request.

Access remains controlled by multiple security layers:

  • Google Workspace authentication
  • Google Sheets document permissions
  • TeamOne configuration permissions
  • IBM Planning Analytics authentication
  • IBM Planning Analytics authorization and data security
  • customer network and infrastructure controls
  • TeamOne Proxy Server allowed-host restrictions

Deployment Models ​

TeamOne Proxy Server supports two common SSL/TLS deployment models.

SSL Managed by a Load Balancer ​

In this model, the customer manages the SSL/TLS certificate on a load balancer.

text
User Browser
    ↓
HTTPS / TLS 443
    ↓
Customer Load Balancer
    ↓
HTTP 80
    ↓
TeamOne Proxy Server
    ↓
IBM Planning Analytics / TM1

The load balancer provides the externally accessible HTTPS endpoint and forwards trusted internal HTTP traffic to the TeamOne Proxy Server.

This model is commonly used in AWS and other enterprise cloud environments because certificate management and renewal can remain within the customer's existing infrastructure.

TeamOne Proxy Server uses TCP port 80 as the default HTTP listener port when SSL/TLS is managed by a load balancer.

Refer to the following Nginx configuration template to manage the default HTTP listener and related proxy settings:

text
config/nginx-http.conf.example

SSL Managed by TeamOne Proxy Server ​

In this model, the SSL/TLS certificate and private key are installed directly on the TeamOne Proxy Server.

text
User Browser
    ↓
HTTPS / TLS 443
    ↓
TeamOne Proxy Server
    ↓
IBM Planning Analytics / TM1

The TeamOne Proxy Server terminates HTTPS directly and manages the certificate files used by Nginx.

TeamOne Proxy Server uses TCP port 443 as the default HTTPS listener port when SSL/TLS certificates are installed and managed directly on the TeamOne Proxy Server.

Refer to the following Nginx configuration template to manage the default HTTPS listener and related SSL/TLS settings:

text
config/nginx-https.conf.example

A load balancer can still be used in front of the TeamOne Proxy Server in this deployment model. In that case, the load balancer forwards HTTPS traffic to the TeamOne Proxy Server, while the SSL/TLS certificate and private key remain installed and managed directly on the TeamOne Proxy Server.

SSL/TLS Certificates ​

The external TeamOne Proxy endpoint must use HTTPS.

The load balancer or TeamOne Proxy Server may use:

  • a publicly trusted SSL/TLS certificate
  • a certificate issued by the customer's internal Certificate Authority (CA)
  • a self-signed certificate

For internal CA or self-signed certificates, the required certificate trust must be established on users' devices and browsers through the customer's standard IT or device-management processes.

If the browser does not trust the certificate presented by the TeamOne endpoint, TeamOne connections may fail.

Public Address-Space Requirement ​

The TeamOne Proxy Server endpoint must resolve to an IP address that the browser treats as belonging to public address space.

This requirement is related to browser Local Network Access security restrictions when Google Sheets communicates with customer-hosted services.

The endpoint does not need to be openly accessible from the public internet.

Customers can restrict access using controls such as:

  • corporate source IP ranges
  • VPN egress ranges
  • Zscaler or equivalent secure access services
  • load balancer security rules
  • AWS security groups
  • firewall policies

The important distinction is that the TeamOne endpoint must use public address space while access to that endpoint can still be restricted to approved users and network paths.

Network Access ​

A typical deployment separates inbound and outbound access.

Inbound Access ​

Users access the TeamOne endpoint through their browser.

For load-balancer deployments:

text
Approved User Network
        ↓
HTTPS / TLS 443
        ↓
Customer Load Balancer
        ↓
HTTP 80
        ↓
TeamOne Proxy Server

The TeamOne Proxy Server should not normally be directly accessible from the public internet.

Inbound access to the proxy should be limited to the approved load balancer or other customer-managed network path.

Outbound Access ​

The TeamOne Proxy Server must be able to communicate with the IBM Planning Analytics / TM1 REST API endpoints configured in TeamOne.

TM1 environments commonly run multiple TM1 instances using different REST API ports.

Customers can restrict outbound access by:

  • approved TM1 hostname or IP address
  • approved TM1 REST API ports
  • both hostname/IP and port

Where multiple TM1 instances use different ports, customers may choose to restrict access by approved TM1 hosts/IPs and use TeamOne's application-level allowed-host configuration as an additional security control.

Allowed Host Configuration ​

TeamOne Proxy Server includes application-level controls that restrict which hosts can be accessed through the proxy.

These settings are configured in:

text
teamone-server-distr/config/.env

TM1 Hosts ​

PROXY_ALLOWED_HOST_PATTERN controls which IBM Planning Analytics / TM1 hosts can be accessed through the TeamOne proxy.

Example using specific hosts:

properties
PROXY_ALLOWED_HOST_PATTERN=tm1-prod.internal.company.com,tm1-dev.internal.company.com

A wildcard can also be used for a trusted internal domain:

properties
PROXY_ALLOWED_HOST_PATTERN=*.internal.company.com

Avoid overly broad patterns such as:

properties
*
*.com

in production environments.

Cognos SSO / OAuth Hosts ​

PROXY_OAUTH_ALLOWED_HOST_PATTERN controls which hosts can be used by TeamOne OAuth/SSO endpoints.

These include:

text
/oauth/login/
/oauth/token/
/oauth/logout/

For IBM Planning Analytics Local using Cognos authentication, this should normally contain the Cognos Gateway hostname configured in the ClientCAMURI parameter in tm1s.cfg.

For example:

ini
ClientCAMURI=https://cognos.company.com/ibmcognos/bi/v1/disp

Configure:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=cognos.company.com

Use the hostname only, not the full URL or path.

Multiple hosts can be separated with commas:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=cognos-prod.company.com,cognos-qa.company.com

Wildcard patterns are also supported:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=*.company.com

If Cognos SSO is not used, configure a non-matching value:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=disabled.local

Authentication ​

TeamOne supports IBM Planning Analytics Local environments with and without SSO.

Without SSO ​

Users authenticate using the IBM Planning Analytics authentication method configured for the TM1 server.

The TeamOne Proxy Server forwards the authenticated requests to IBM Planning Analytics.

IBM Planning Analytics remains responsible for validating the user and enforcing all security permissions.

With Cognos SSO ​

For environments using IBM Cognos-based authentication, TeamOne can support the existing Cognos login flow.

The TeamOne Proxy Server facilitates communication between TeamOne, the Cognos Gateway, the customer's identity provider, and IBM Planning Analytics.

The existing customer identity provider may include services such as:

  • Microsoft Entra ID
  • Google Cloud Identity
  • Okta
  • other identity providers integrated with IBM Cognos Analytics

After authentication, IBM Planning Analytics continues to enforce the authenticated user's TM1 security permissions.
