TeamOne Proxy Server Troubleshooting ​

Use the checks below if the TeamOne Proxy Server is not starting, is not reachable, or cannot connect to IBM Planning Analytics / TM1.

For questions or assistance, contact teamone@succeedium.com.

Confirm the Docker Containers Are Running ​

Run:

bash
sudo docker ps

Both the teamone and nginx containers should be running.

Check the Nginx Logs ​

bash
sudo docker logs --tail=200 nginx

Use this to investigate:

  • Nginx startup errors
  • configuration errors
  • certificate loading errors
  • HTTP / HTTPS listener issues

Check the TeamOne Application Logs ​

bash
sudo docker logs --tail=200 teamone

Use this to investigate:

  • application startup errors
  • request handling errors
  • proxy errors
  • connectivity issues to IBM Planning Analytics / TM1

Test the TeamOne Application Backend ​

The TeamOne application listens internally on port 8000.

Run:

bash
curl http://localhost:8000/

A JSON response confirms that the TeamOne application backend is running.

Load Balancer SSL Deployments ​

For deployments where SSL/TLS is managed by a load balancer, Nginx receives HTTP traffic from the load balancer.

The default TeamOne Proxy Server HTTP listener port is 80.

Test locally:

bash
curl -v http://localhost/

If this succeeds locally but the external TeamOne URL does not work, review the load balancer target, listener, routing, and network access rules.

The expected traffic flow is:

text
User Browser
    ↓
HTTPS / TLS 443
    ↓
Customer Load Balancer
    ↓
HTTP 80
    ↓
TeamOne Proxy Server

Confirm that the load balancer forwards traffic to the correct TeamOne Proxy Server host and port.

Direct SSL Deployments ​

For deployments where the SSL/TLS certificate is installed directly on the TeamOne Proxy Server, Nginx listens for HTTPS traffic.

The default HTTPS listener port is 443.

Test locally:

bash
curl -vk https://localhost/

A successful response confirms that Nginx is accepting HTTPS connections.

Confirm the Active Nginx Configuration ​

Run:

bash
sudo docker exec -it nginx nginx -T

For load balancer SSL deployments, confirm that the HTTP listener is configured.

For direct SSL deployments, confirm that SSL certificate directives are present:

bash
sudo docker exec -it nginx nginx -T | grep ssl_certificate

Direct SSL: Confirm Certificate Files ​

If SSL/TLS is managed directly by the TeamOne Proxy Server, confirm the certificate and key exist inside the Nginx container:

bash
sudo docker exec -it nginx ls -l /etc/nginx/certs

The expected files are:

text
teamone.crt
teamone.key

Direct SSL: Validate the Certificate and Private Key ​

From the teamone-server-distr directory, run:

bash
openssl x509 -in cert/teamone.crt -text -noout
openssl rsa -in cert/teamone.key -check -noout

To confirm that the certificate and private key match:

bash
openssl x509 -noout -modulus -in cert/teamone.crt | openssl md5
openssl rsa -noout -modulus -in cert/teamone.key | openssl md5

The two hashes should match.

Verify the TeamOne Proxy URL ​

Open:

text
https://<teamone-proxy-fqdn>

Confirm that it displays:

text
TeamOne is up!

If the browser reports a certificate warning, confirm that the certificate used by the load balancer or TeamOne Proxy Server is trusted by the user's device and browser.

Test IBM Planning Analytics / TM1 Connectivity ​

Use the TeamOne Proxy Server to request the TM1 REST API metadata endpoint.

Example using HTTPS for the TM1 connection:

text
https://<teamone-proxy-fqdn>/?url=https://<tm1-host>:<tm1-rest-api-port>/api/v1/$metadata

Example using HTTP for the TM1 connection:

text
https://<teamone-proxy-fqdn>/?url=http://<tm1-host>:<tm1-rest-api-port>/api/v1/$metadata

If the TeamOne Proxy Server itself is reachable but the TM1 request fails, check:

  • the TM1 hostname
  • the TM1 REST API port
  • whether TM1 uses HTTP or HTTPS
  • outbound firewall or security group rules
  • PROXY_ALLOWED_HOST_PATTERN
  • DNS resolution from the TeamOne Proxy Server
  • IBM Planning Analytics / TM1 availability

Check Allowed Host Configuration ​

Review:

text
teamone-server-distr/config/.env

Confirm that the required TM1 host is included in:

properties
PROXY_ALLOWED_HOST_PATTERN=

If Cognos SSO is used, confirm that the Cognos Gateway host is included in:

properties
PROXY_OAUTH_ALLOWED_HOST_PATTERN=

After changing .env, recreate the containers:

bash
sudo docker-compose -f teamone-server-distr/docker-compose.yml up -d --force-recreate

Recreate the Containers ​

If configuration changes are not being applied or one of the containers is in an unexpected state, recreate them:

bash
sudo docker-compose -f teamone-server-distr/docker-compose.yml down
sudo docker-compose -f teamone-server-distr/docker-compose.yml up -d

Then confirm:

bash
sudo docker ps
